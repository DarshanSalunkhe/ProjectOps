# Bug fix report

## Fixed

| Defect | Change | Verification |
|---|---|---|
| Project task creation route allowed any project member and trusted the submitted project ID | Require OWNER/DEVELOPER and validate body `project_id` matches the project in the route | Syntax check passed; HTTP regression blocked by database outage |
| Task creation UI omitted required `project_id` and sent empty optional date/hour values | Inject the route project ID and omit blank optional fields from the request | Frontend payload regression added |
| Milestone update/delete required authentication only | Load milestone, verify project membership, and require OWNER/DEVELOPER | Syntax check passed; HTTP regression blocked |
| Task skill requirements and matching lacked task membership authorization | Require task access for reads and matching; OWNER/DEVELOPER for modifications | Syntax check passed; HTTP regression blocked |
| Impact route lacked task access authorization | Added task membership guard | Syntax check passed; HTTP regression blocked |
| Dependency delete could delete a dependency from a different task via its ID | Scope deletion to the task URL; mismatches return 404 | Service regression not separately run; syntax check passed |
| Skill matcher emitted a bitwise expression result for `match` | Return the `exact` or `exceeds` string based on proficiency comparison | Syntax check passed |
| Skill matching considered users outside the project and calculated string hours incorrectly | Query members of the task’s project; convert workload/capacity to numbers and enforce available capacity | Unit service tests do not cover database query; live check blocked |
| AI plan apply omitted task creator and ignored generated skills | Pass the authenticated creator to task persistence and save each generated skill as an intermediate mandatory requirement | Regression test passes with repository doubles |
| AI plan apply accepted duplicate task IDs and invalid dependency references | Reject duplicate IDs, missing endpoints, and self-edges before writes | Source fix; endpoint check blocked |
| AI plan application could leave a partial project when a later write failed | Apply task, skill, dependency, and milestone writes through one transaction client; commit only after all writes and roll back on errors | Regression verifies every repository write receives the same client; DB rollback remains unverified |
| Impact analysis treated only the first successor as direct and did not expose `affectedTasks` | Classify all direct successors by graph edge and return the full list; constrain delay input | Two focused impact regressions pass |
| Replanning omitted milestone repository and used nonexistent `affectedTasks` field | Pass milestone repository, consume normalized impact tasks, and calculate utilization from numeric project-member values | Replanning regression passes |
| Task status/estimate updates and deletion left assigned-user workload stale | Recalculate from existing assignments after updates/deletion | Syntax checks pass; DB workflow blocked |
| Dependency UI expected a different graph shape; AI assignment UI double-unwrapped API data | Normalize the returned edge graph to list fields and read response payload once | Frontend production build passes; browser workflow blocked |
| Recovery proposals had no approval or persistence path | Add saved proposals, owner-only apply, project snapshot/staleness validation, atomic assignment/date changes, and applied-state tracking | Migration 015 and live isolated OWNER apply/reject/persistence tests pass |
| Recovery UI still showed “Application unavailable” and lost a proposal on refresh | Load the latest persisted proposal, require explicit review, and wire owner approve/apply and reject decisions to transactional API routes | Regression checks and live isolated proposal reload/apply/reject workflow pass |
| Authentication accepted stale token claims when session revocation or user lookup could not reach PostgreSQL | Return 503 for identity-store connection errors; only continue authentication after revocation and fresh-user checks succeed | Three isolated middleware tests pass: 503 for each DB failure path and 401 for revoked session |
| Recovery apply rejected a valid date after delay analysis because a PostgreSQL DATE became a UTC timestamp in JSON | Normalize impacted task deadlines to canonical `YYYY-MM-DD` before persisting proposals | Date-boundary regression passes; real isolated OWNER apply advanced and persisted the downstream deadline |
| Recovery snapshot sent concurrent queries through one `pg` Client | Run task, assignment, and dependency snapshot reads sequentially; create the proposal using the already checked client | Full real isolated proposal generation passes without the prior same-client deprecation warning |
| Health score returned 100/HEALTHY for a project with zero tasks | Pass task count into health scoring; return null and `INSUFFICIENT_DATA` when there are no tasks; update UI displays to avoid `—/100` | New backend regression passes in the 14-test suite; live UI/database verification blocked by Neon timeout |
| Non-production database config overrode SSL settings in `DATABASE_URL` | Preserve the connection-string SSL mode; only supply a production SSL fallback when the URL has no mode | Syntax/build and isolated Neon migration/E2E connections pass; reachability remains intermittent |
| Playwright setup timed out before browser assertions | Installed matching Chromium, corrected web-server cwd/paths, bounded test-mode DB connection startup, and captured screenshot, trace, console, and network evidence on failure | Fresh public run: 5 passed, 1 skipped after DB health reported disconnected. Authenticated planner attempt received HTTP 503 during fixture creation. Earlier API E2E pass is historical; raw output is not retained. |
